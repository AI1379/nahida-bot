# 核心重构第一阶段：记忆可见性与主动错误通知

2026-11-15。按 owner 本轮反馈收敛；以下区分本阶段实现与后续讨论。未部署、未修改生产数据。

## 本阶段交付

- 保留现有自动回复、分段文本和 RP 上下文语义；不启用 #67 工具发送模式。
- 将运行失败与正文分开判断，保留失败/未完成/取消终态。主动错误默认静默，普通成功回复继续发送。
- Sessions 页面提供会话错误通知策略，持久化到 `sessions.metadata_json.runtime.error_notifications`。
- Memory 页面显示所选 scope 的全量存储统计，以及条目的主体、可迁移性、结构化证据和原文。
- 只保留针对失败外发、来源归属与管理接口的必要回归，不建设复杂事故回放平台。

### 错误通知

| mode | 行为 |
|---|---|
| `interactive`（默认） | 私聊、@、命令等明确交互显示错误；Conversation Joiner、未被直接呼叫的群消息和 CRON 静默 |
| `none` | 本会话的运行错误/中断通知全部静默 |
| `all` | 各种触发均可显示运行错误/中断通知 |

策略在发送错误时读取。它不限制正常回复、显式工具发送或独立插件自行生成的通知，不通过搜索文本中的 error 关键词判定失败。
已经发送的正常中间回复不撤回。失败终态的兜底正文不作为新 assistant 记忆进入固化；先前正常回复及工具已发送的话语仍保留。
CRON 的失败结果计入失败状态，不将非空兜底文本当作成功结果；是否通知由创建来源 session 决定，没有来源时使用 job 的 session_key。

策略属于具体 session，`/new` 后采用默认值；不暗中提升为整个群的永久配置。静默仍保留日志、run 终态和 CRON last_error。
管理接口只接受枚举值，不接受任意 metadata/config patch；并发 reasoning 设置与错误策略修改通过原子 runtime patch 保留彼此字段。

### 记忆管理视图

统计包括总数、活跃、归档、受限、待处理候选，以及缺少结构化主体/证据字段的数量。按 scope 统计，不受列表前 150 条限制，也不随搜索/分类变化。
缺少字段不表示内容已确认错误；来源字段不等于可靠事实。scope 最多展示数量最多的 50 个，界面注明截断。
详情最多展示 50 个证据引用，每个原文最多 12,000 字符，均标注截断。记录不存在与引用冲突分别显示，不拿别人的原文充当证据。
工具即时写入的证据尚无 turn_id 时，可通过原 session 和 message_id 查回；不跨未知 session 猜测。
归档条目可以按 ID 管理查看，普通记忆检索保持 active-only。管理 API 复用现有 Gateway 操作者鉴权，不对普通聊天工具暴露。

这是存储状态视图，不声称重放某次模型运行的完整提示词。原始 Metadata 保留折叠查看。

## 后续权限与记忆共同讨论的边界

目前跨会话原始历史工具受 `authorization.chat_domains` 限制；结构化记忆的 scope、sensitivity、portable 与 soft-scope 是另一套规则。
本阶段展示差异，不先把它们强行合并，也不改变公开跨群回忆或私聊记忆规则。下一步应以真实查询场景制定一张读取矩阵：

| 查询场景 | 需要明确的边界 |
|---|---|
| 当前聊天记录 | 当前聊天归属与历史 lane，避免混入其他会话 |
| 同社区其他群记录 | chat_domains 范围、来源标注、当前受众 |
| 其他私聊 | 请求者参与关系与公开转述范围，不能由群成员身份推导 |
| 同 Person 跨渠道记忆 | 已确认账号关联、隐私与解绑后的可见性 |
| 公开人物事实/关系 | 主体与发言者分开；公开与可迁移不等于所有上下文都适用 |
| owner 管理查看 | 明确的管理视图；管理者读到不等于允许向当前群复述 |

现有认证账号、Person、来源聊天、回复目标与可信终态继续作为基础契约。后续围绕具体读取/写入入口收口，不增加通用角色树、策略语言或授权票据平台。

## exec 的简化方向

保留普通用户做搜索、计算、资料整理和产物生成的能力，避免回到一刀切禁用 exec。宿主机完全放开也不作为可接受的替代方案。
优先验证维护中的 Linux 工具组合（例如 systemd 资源控制与现成隔离启动工具），先完成只读资料＋任务目录＋离线计算的最小路径。
公网读取先复用现有受控工具；需要联网脚本时单独验证出口与可访问数据的组合，不自行开发网络代理/完整沙箱平台。
不给脚本继承生产凭据、数据库、渠道接口、SSH agent 或宿主控制 socket；隔离不可用不回退宿主执行。

旧 `linux-execution-isolation.md` 中独立特权 broker、通用能力体系等属于较大方案，不作为本轮第一阶段的交付要求。
此阶段未安装 Linux 组件、未改 authorization.mode、未限制现有 exec，也未重启服务器。后续需在服务器实际能力与权限条件下验证最小方案。

## 显式发送暂缓

在改变发送方式前，单独评估 RP 连贯性、旧 assistant 历史、工具话语记忆、分段/流式输出、模型工具遵从性和静默率。
本阶段只调整失败通知，不把长回复、普通旁白或“含 error 字样的正常内容”当成错误过滤。

## 下一阶段优先级

1. 利用新管理视图审阅实际记忆状态，明确主体纠错、替换链与派生摘要失效需求。
2. 为原始历史与长期记忆形成共同的受众/来源读取矩阵，再决定哪些入口需要改动。
3. 验证最小 Linux 执行路径，确定可用能力和部署成本。
4. 完成请求/终态在所有入口的传播后，再评估消息显式发送。
