## 结论

按用户补充意见，提供真正默认放行的可选模式：在所选运行环境和资源边界内，不要求逐项列入能力白名单；未命中明确危险规则的动作可以直接执行，包括搜索、搜图、目录检索与临时脚本。

保留标准模式，增加宽松模式和危险模式。模式决定默认放行策略；资源、身份与额度机制提供执行边界。不能把恶意识别器的“未检出”解释为安全证明，也不能把程序异常、网络失败和权限拒绝混为一谈。

## 可选模式：本次方案的主要调整

| 模式 | 默认策略 | 脚本执行 | 适用场景 |
|---|---|---|---|
| `standard` 标准 | 按明确能力与资源授权 | 已授权固定任务或隔离计算 | 默认部署、陌生群 |
| `relaxed` 宽松 | 边界内默认放行，只拒绝明确危险行为 | 允许临时 Python/shell，运行于隔离环境 | 日常社区、用户选择的群 |
| `unsafe` 危险 | 跳过原有通用管理员门槛，危险检测可拦截或只审计 | 可使用 bot 服务账号执行宿主机命令 | 操作者明确接受较大风险的环境 |

模式由部署者为账号、聊天或聊天域配置，普通用户仅能在部署者允许的模式集合中选择。模式选择不改变管理员身份，也不能由聊天文本、网页或模型参数自行切换。各群独立配置，不能把某群开启危险模式传播到其他群。

推荐先在指定社区启用 `relaxed`，其他聊天保留 `standard`。`unsafe` 默认关闭；部署者可以同时选择检测为 `enforce`（命中则拦截）或 `audit`（只记录），并明确审核服务不可用时是暂停还是继续。`audit` 下不能声称还能阻止明显攻击。模式与检测选项写入配置和审计记录，而非藏在提示词里。

### “明显危险”的判断方式

先检查具体动作，再用模型辅助理解上下文，不能只对用户原话做善恶分类：

1. 确定性检查关注资源和副作用，例如实际目标是凭据、生产数据库、权限配置，或请求把本地敏感内容发送给外站；不靠 `rm`、`python` 等字符串黑名单判定。
2. 对脚本、浏览器操作和陌生远端工具使用独立审查上下文，对照原始任务判断是否突然增加读取密钥、外传文件、破坏数据、持久化或扩大权限等行为。要求返回具体动作证据，不接受模糊的“可能危险”。
3. `relaxed` 下，只因“这是脚本”“调用网络”“没有见过这个工具”或低置信度怀疑，不拒绝边界内执行；记录后放行。已知越界或有明确危险证据才阻止。
4. 模型只作辅助，网页、图像页面、工具返回中的指令都是不可信数据。给审查器的数据也要限制和脱敏。脚本可能编码、动态加载或分多步执行，因此需要执行环境提供实质保护。

实现上将 `AuthorizationGate` 返回的“缺少管理员身份”变成模式相关的判断：标准模式按原能力规则；宽松模式在边界内允许；危险模式按部署者选择的检测策略执行。认证、模式管理与工具参数校验保持独立，用户不能通过申请一个模式获得修改模式的权限。

### 对用户给出的场景

- **普通搜索**：默认允许公开互联网搜索与读取，保留内网、环回和云元数据访问限制；不要求每个普通公开域名都单独授权。搜索服务不可用时应报能力/配置问题。
- **指定网站搜图**：优先专用搜索/API，必要时使用隔离浏览器或临时脚本；公网请求和图片 CDN 可用，但不继承管理员浏览器登录状态。`web_fetch` 当前是正文提取工具，`html_to_markdown` 明确剥离 `img`，它无法代替完整搜图链路。
- **固定目录 grep**：现有 `search_files` 已免管理员，但需要配置目录，且只支持子串匹配。模型若改用 `exec grep` 会命中管理员门槛。宽松模式可把该目录只读挂载到执行环境，让 grep/rg 和处理结果的脚本正常运行；扩展工具应向模型公开资料源别名和能力范围。
- **临时脚本**：宽松模式允许在隔离环境执行，不需要管理员提前审核每一个脚本。计算、解析网页、绘图、转换文件属于正常用途；执行时间、并发、存储、网络出口受到环境限制。

`search_files` 还需补逐文件路径验证：目前 `_iter_files` 返回的文件随后直接 `stat/read_text`，根目录内指向外部的文件符号链接存在被跟随的路径。只验证最初的 `path` 和关闭目录链接遍历不足以覆盖这一情形。扩大目录开放前应补检查和回归测试。

### 宽松与危险模式的实际差别

宽松模式的“默认放行”由隔离环境兜底：只读挂载批准的资料目录，个人输出目录可写，开放受控公网出口，不提供宿主凭据、生产 DB 或管理员登录状态。任意脚本的网络连接也必须经过实际网络隔离/出口策略，不能仅依靠 `web_fetch` 的 URL 校验。

宿主目录、系统管理和远端账户副作用不在隔离环境保护范围内。不能把本地沙箱当作 MCP 远端写操作的安全保证；这些目标需要单独资源授权或危险模式显式覆盖。

危险模式允许跳过通用管理员门槛并在宿主机执行，意味着脚本可能读写 bot 服务账号可访问的文件、使用其网络权限，即使发起者仍名义上不是管理员。命令审查无法等价替代 OS 隔离。可使用独立低权限服务账号、独立实例、备份和额度降低影响，但这是降低损害，不是消除风险。

## 标准模式能力矩阵

| 动作 | 普通用户默认策略 | 额外授权与限制 |
|---|---|---|
| 公开知识库、已发布资料查询 | 允许 | 资料源明确标记可公开；受限资料绑定账号或聊天域 |
| 当前聊天历史 | 允许 | 聊天上下文来自服务端 |
| 同域历史 | 按现有聊天域配置允许 | 域共享的是阅读范围，不自动授予跨群写入或发言权 |
| 私聊或其他社区历史 | 不自动开放 | 独立明确授权；群内操作不能继承用户私聊的数据读取权 |
| 创建笔记、CSV、文档等产物 | 允许 | 服务端分配个人产物区，独立于指令、代码、配置目录 |
| 修改或删除产物 | 允许操作自己的产物 | 校验账号、聊天上下文、所有权和版本；优先可恢复删除 |
| 发送产物或当前聊天上传文件 | 允许发送到当前聊天 | 使用已授权文件句柄，不能指定任意宿主机路径 |
| 计算、绘图、格式转换 | 隔离执行服务就绪后允许 | 无宿主机凭据；限制挂载、网络、CPU、内存、时长和输出 |
| 创建、修改、取消普通提醒 | 允许管理自己的任务 | 当前聊天内生效；任务数、频率、推理成本有限额 |
| 管理群公共定时任务 | 需要该群的任务管理能力 | 群管理者不能编辑他人私有任务，也不能改成脚本执行 |
| 跨群发送通知 | 需要指定来源与目标的通知能力 | 目标群预先加入许可范围；限频；不得借历史阅读域推导发送权 |
| 宿主机 shell、桌面控制、系统指令和配置修改、身份/MCP 管理 | 管理员 | 不包含在普通用户或群管理能力包内 |

“公开”“只读”都需要看数据来源。只读密钥文件、桌面截图和他人聊天记录不是低风险功能。

## 各模式复用的最小实现模型

以现有 `AuthorizationGate` 为统一策略入口，扩展注册元数据和决策结果，不引入通用策略语言或外部权限平台。

- **主体**：平台认证的账号键；不得由模型参数、昵称、Person 合并或记忆内容指定。
- **能力**：如 `reference.read`、`artifact.write`、`compute.run`、`cron.manage_own`、`chat.notify`、`system.exec`。能力包只是这些授权的配置快捷方式。
- **资源**：资料集合、产物句柄、任务 ID、规范化聊天地址等；服务端从可信上下文和资源记录解析。
- **约束**：所有者、聊天域、目标列表、有效期、次数、文件大小及成本预算。
- **决策**：允许、拒绝或缺少一项可补授的明确能力，同时返回机器可读原因及可行替代工具。

执行顺序：确认可信主体与上下文 → 解析资源 → 匹配能力和硬性限制 → 原子预占额度 → 执行 → 结算额度与记录结果。并行工具、子代理、定时任务共享适用的账号/群组预算，避免拆分任务绕过限额。

工具列表按当前主体与模式预过滤；需要参数才能决定的工具展示约束或提供范围明确的变体。执行前仍然执行所选模式的策略，隐藏工具不能代替安全检查。

保留原有管理员工具标记作为标准模式的迁移期兜底，其他模式在统一决策入口覆盖其行为，不全局删除标记。标准模式中新注册且未分类的工具不自动向普通用户开放；宽松模式中的新工具如能确定副作用受执行边界约束，可以默认放行。远端未知副作用不能声称受到本地隔离保护。

## 文件与执行的具体边界

第一阶段可以增加 `artifact_create/read/update/send`。产物保存在不被启动指令、技能加载器或脚本调度自动扫描的独立目录，记录 owner、来源聊天和版本。返回不透明 ID，后续操作通过 ID 校验授权。目录路径校验须覆盖 `..`、符号链接、Windows junction，以及验证与打开之间的竞态；不能只检查字符串前缀。

普通用户上传或生成的脚本、提示文本均作为数据保存，不自动成为受信任代码或系统提示。发送至群的内容属于明确共享内容；尚未发送的个人产物不能因位于同一聊天或工作区就被其他用户读取。共享编辑区需要显式开放。

复杂文档和计算依赖第二阶段的隔离执行服务。优先提供结构化转换/计算工具；任意 Python 等代码只能在真正隔离的进程环境执行，输入采用授权副本，输出经大小与类型检查后导入产物区。默认关闭外网，需要联网的功能使用单独受控出口；不挂载生产 DB、密钥、宿主机 socket 或整个项目目录。超时后清理整棵进程树。

不要用“禁止 rm/sudo”“允许 python/grep 开头”或让 LLM 判断命令安全来替代隔离。隔离服务不可用时明确说明对应能力暂不可用，不回退到宿主机 shell。

## 委派、自动任务与插件

- 子代理的权限只能取发起者授权、父任务范围和子任务请求范围的交集；保留既有系统禁止委派清单。
- 定时任务保存真实发起者、资源范围及创建时能力上限；每次运行重新检查当前授权。创建后提权不使旧任务自动升级，撤权后下一次执行失效。
- 群聊自动加入、多用户合并消息不能把管理员发言的身份借给其他人的请求；无法可靠绑定动作发起者时只使用群默认安全能力。
- 单次临时授权作为后续可选功能，仅由有授予权的人创建，绑定主体、具体资源/动作、有效期与使用次数。参数改变超出批准范围时失效，不发放一段时间的全局管理员身份。
- MCP 的远端只读声明仅供参考。由本地配置审核每个服务/工具的能力和资源范围；未知工具默认受限。服务安装、移除、重连归系统管理。
- 插件 manifest 权限与用户权限取交集，不能将“插件能写文件”推导成“任何用户都能要求它写任何文件”。高影响 API 需要统一资源校验，避免换一个包装工具绕过限制，同时保留 `plan` 这类固定用途写入的合适权限。
- 现有插件在宿主进程内运行，属于受信任代码；API 权限检查不能声称能隔离恶意 Python 插件。引入不可信插件需要另做进程隔离。
- 保持授权与记忆模块解耦：记忆仍按原有可见性与归属规则工作，不在 memory/retrieval 内引入管理员判断。

## 建议首轮默认额度

以下仅为可调起点，不是已经验证的生产阈值：每账号最多 10 个活跃普通提醒，重复任务最短间隔 5 分钟；个人产物区 100 MB；隔离计算每次最多 30 秒、512 MB 内存、2 个并发。按群追加聚合预算，防止多个用户同时耗尽服务资源。

外部付费 API 单独限制调用量或费用；额度耗尽返回“何时恢复/如何缩小任务”，而不是“需要管理员”。这些数值应结合生产任务分布调整，现有任务迁移要报告超额情况，不静默删除。

## 标准模式与公共基础的实施和验收

1. **先分类与解释**：梳理实际注册工具，记录结构化拒绝原因，补齐 MCP 管理鉴权，分离授权开关；给普通用户展示安全工具和替代路线。保存策略版本与回滚方式，回滚不能关闭全部鉴权。
2. **开放有界产物**：实现个人产物区、所有权校验与当前聊天发送。验收“帮我生成一个 CSV 并发到群里”不需要管理员；他人产物、系统指令和越界路径不可访问。
3. **补资源授权与额度**：复用聊天域和 cron owner 基础，增加群任务管理及按目标授权的通知；处理 owner 缺失的旧任务。验收本群附加权限不能作用于其他群。
4. **增加隔离计算**：验证无宿主凭据与目录、无默认外网、资源上限和进程回收后开放普通用户。验收同一绘图需求成功，读取生产库或宿主文件失败。
5. **按需增加临时授权**：优先依靠默认能力与长期有限授权满足常见任务，临时审批只解决少量明确越界需求。

策略测试须覆盖主体伪造、修改目标参数、同域读取与发言权分离、双路径授权一致性、文件越界/归属/覆盖、MCP 未分类工具、权限撤销、子代理与 cron 委派、多用户自动加入、并发配额竞争。上线后同时观察低风险任务完成率、拒绝原因分布、敏感越界拦截和预算消耗。
