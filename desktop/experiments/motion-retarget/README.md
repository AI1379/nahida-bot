`http://127.0.0.1:1420/experiments/motion-retarget/index.html`

- `Nahida_1080/Nahida_1080.model3.json` 及其模型资源。

- `_motion-lab/live2d.min.js`：Cubism 2 Core；来源为 pixi-live2d-display README 指向的

## 已确认的事实

- 原动作 30 fps、110 帧、约 3.633 秒，包含 65 个参数通道。
- 原动作俯仰范围为 -27 到 +17，侧倾到 -14；末尾保留俯仰 -9.07、侧倾 -14。
- 源/目标头部参数范围均为 -30 到 +30；数值相同不能证明可视动作等价。
- 源眼睛范围 0–1.5、默认 1；目标范围 0–约 1.2、默认 1。
- 旧转换的头部数值与源曲线一致；眼睛已经除以 1.5，**旧文件没有眼睛截断错误**。
- 旧导出不包含源模型的手臂/手形，不能把其表演损失全部归因于头部曲线。

## 第一轮手动候选的变化（未通过迁移保真验证）

默认俯仰增益 0.55、侧倾增益 0.25、身体增益 0.4。保留原点头和眨眼的采样时序；
以目标休息姿态为基准，从 1.5 秒开始用 0.75 秒平滑回正。导出约 2.267 秒、69 帧、11 条曲线。
原版持续保持的末尾姿态在这个独立点头候选中被有意移除。

眼睛以源动作开头的 1.5 睁眼姿态对应目标默认睁眼值，保留闭合比例；这是一项针对本动作的
风格选择，不应推广成所有动作都以第一帧为中性姿态。保留目标支持的眉角度，忽略不存在的绑定
及没有变化的通道。头发和衣物使用目标模型的物理，手部暂不迁移。

## 验证口径

`pnpm exec vitest run experiments/motion-retarget/curves.test.js` 检查眼睛比例、时序、末尾回正、
缺失通道和导出采样往返。浏览器开发入口 `motionStudy.verifyNative()` 使用 Cubism 原生
motion3 解码器逐帧核对；该数值核对关闭 SDK 淡入淡出，导出文件本身保留 0.15/0.2 秒淡入淡出。
对照页也按原始曲线直放，因此不等同于带所有运行时图层的桌宠端到端录屏。

用户复核指出了源动作与目标身体侧倾的差异；后续隔离实验支持该问题确实存在。
因此不能以固定时刻的视觉检查或数值测试通过认可该候选。此次没有验证其它角色或其它动作。

## 身体侧倾复核

源曲线确实包含 `PARAM_BODY_ANGLE_Z: 0 → 5`，但源模型只产生轻微可视侧倾。
关闭物理、一次只设置一个参数后，以同一模型变形前后的全网格对应顶点拟合二维仿射变换：

| 单独输入 | 香澄全网格拟合旋转 | 纳西妲全网格拟合旋转 |
|---|---:|---:|
| 身体 Z = 5 | 约 1.25° | 约 6.27° |

这是无权重的全网格几何诊断，包括非躯干网格，不是骨骼角度、动作质量分数或可直接使用的增益。
两个模型网格不同，不能逐顶点跨模型做相减。这里分别测量各自变形，确认同名参数的响应强弱差异。
源模型另有 `PARAM_UPPER_BODY`：在本动作的 -0.45 位置主要体现纵向位移，未被旧转换迁移。
因此不能按名字一对一搬运身体曲线，更不能把头部参数 -14 解释为屏幕上倾斜 14°。

浏览器开发入口 `motionStudy.probeRigs()` 会自动在各选定参数范围的 ±25%、±50% 位置采样，
输出旋转、平移、矩阵与归一化位移；`rig-probe.js` 的量测函数本身不依赖参数命名。
`rig-probe.test.js` 验证旋转/平移区分及退化形状处理。
已有 759 值原生解码核对只能验证序列化后的数值一致，不能证明迁移保真或自然感。

可复用流程应继续到“模型级视觉响应/语义标定 → 多参数联合映射 → 留出动作验证”。
参数扫描只是其中已实现的一步；共同语义参考点和可靠自动标定尚未实现。
